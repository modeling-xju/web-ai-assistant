# 故障排查

按**症状**查。每条都给出：先看什么 → 最可能的原因 → 怎么验 → 怎么修。

先做一件通用的事：**用浏览器开发者工具（F12）的 Network 面板看真实的请求**。挂件这类问题 80% 靠这一眼就能定位，比读代码快得多。看三样：请求发到哪个 URL 了、状态码是多少、响应体第一行是什么。

---

## 对话报 `request error`

AppFlow 挂件最常见的问题。三个成因，按出现频率排序：

### 1. API Key 不可用

- **验**：AppFlow 控制台 → AI 助手详情 → 点已导入模型旁的编辑图标 → 「选择连接凭证」步骤里看到 API Key → 去百炼控制台「密钥管理」页面确认这个 key 的状态（是否被禁用、是否被删除）。
- **修**：重建一个 API Key，回 AppFlow 的凭证里更新。

### 2. 智能体与 API Key 不在同一个业务空间

这条最隐蔽，因为两个值看起来都"对"。

- **验**：AppFlow 配置的「参数配置」步骤里看 **业务空间标识（AgentKey）**；对比百炼里这个应用和这个 API Key 分别属于哪个业务空间。**分属不同业务空间会导致鉴权失败。**
- **修**：统一到同一个业务空间（换 key 或换应用，取决于哪边动起来代价小）。

### 3. 应用 ID 填错

- **验**：「参数配置」步骤里确认 **应用 Id** 的值，拿去百炼「应用管理」页面逐个对比。
- **修**：改成正确的。

三项都对之后助手就能正常对话。排查顺序建议就按 1→2→3，因为第 1 项最容易验。

## `Failed to stream content`

**前端的请求地址配置错了。** 官方文档明确指出的成因是：定制前端组件时直接抄了示例代码里的默认地址（如 `/chat`），没有替换成真实的后端服务地址。

- **验**：F12 → Network → 看聊天请求打到哪个 URL。如果是个相对路径、或者别人的域名，就是它。
- **修**：
  - 用 AppFlow 官方挂件的话，**确保脚本来自你自己的 AI 助手 Web 集成页面**，而不是别处抄来的示例。别人的 `requestDomain` 是别人的域名。
  - 自建挂件的话，检查 `data-endpoint` / `mount({endpoint})` 是否指向真实存在的后端。
- **顺带确认**：模型配置正确——API Key 和应用 ID 都填了。

## 挂件图标根本不出来

按顺序排除：

1. **`APPFLOW_CHAT_SDK is undefined`（控制台报这个）**
   典型成因是把 SDK 的 `<script>` 加了 `defer`，而 `init` 写在后面的内联 `<script>` 里。内联脚本先于 defer 脚本执行。修法见 `appflow-sdk.md` 的「初始化时序」，或直接用 `assets/appflow-snippet.html`。
2. **被站点自己的样式盖住了**
   在 Elements 面板选到挂件的容器，看 `z-index` 与 `position`。挂件通常是 `position: fixed`，如果站点有更高的 `z-index` 层（弹窗、吸底导航）就会盖住。自建挂件把 `zIndex` 配置调高。
3. **父容器裁掉了它**
   如果挂件被放进了一个 `overflow: hidden` 或 `transform` 过的容器，`position: fixed` 会失效（被最近的 `transform` 祖先变成包含块）。自建挂件默认挂在 `document.body` 上，就是为了避免这件事；若你手动改了挂载点，改回去。
4. **`transform` 祖先导致 fixed 失效**
   同上。在 Elements 里从挂件往上找，看有没有带 `transform` / `filter` / `will-change` 的祖先。
5. **SPA 里被路由反复挂载 / 卸载**
   表现是图标有时候有一堆、有时候一个都没有。放到应用入口挂一次。

## 挂件和站点样式互相打架

自建挂件用 Shadow DOM 隔离，正常情况下不会发生。如果发生了，通常是：

- **有人把 Shadow DOM 去掉了。** 检查 `attachShadow` 是否还在（比如为了"方便调样式"改成了普通 div）。这是最常见的自毁。
- **站点用了 `!important` 的全局规则针对所有元素。** 极少见，但如果真有（例如 `* { color: red !important }`），`!important` **能穿透 Shadow DOM**。这种情况只能在挂件自己的样式里也用 `!important`，或者跟站点协商收窄那条规则。
- **挂件的样式表 404 了。** 表现是"挂件出来了但没样式"（裸 HTML 的样子）。F12 Network 里找 `.css` 请求。原因通常是只拷了 `.js` 没拷 `.css`，或者 `cssUrl` 路径写错。

反向的问题（站点被挂件污染）几乎不可能——除非你改成了非 Shadow DOM 挂载。

## 助手答不准 / 满嘴瞎编

按性价比排序，从上往下试：

1. **Prompt 里没写边界。** 加"只回答与本站产品相关的问题，不知道就说不知道，不要编造"。这一句能消掉大部分瞎编。
2. **没接知识库，或知识库没生效。** 检查百炼「应用管理」里应用是否挂了目标知识库、调用方式是否选了**必定调用**、以及挂完之后有没有重新**发布**（改了不发布 = 没改）。
3. **知识库文档本身质量差。** 扫描版 PDF、表格转坏的文件，检索出来的片段就是垃圾。换文字版。
4. **切分策略。** 最后再动，也最玄学。

另一个常见情况：**助手不知道用户在看什么**。这不是模型的问题，是你没传上下文。用 `extraInfo` / `setExtraInfo` 把当前页面、当前商品 ID 传进去。

## 回复"憋一大段才出来"，不是流式

- **中间有 Nginx**：加响应头 `X-Accel-Buffering: no`。Nginx 默认会缓冲响应体，流式就变成了攒完再发。
- **后端没开流式**：检查上游请求里的 `stream: true`，以及后端有没有把上游的 SSE 帧原样转发（而不是 `await res.json()` 之后再整体写回）。
- **后端框架自己缓冲**：某些框架需要显式关闭压缩中间件（gzip 会把 SSE 也缓冲住）。挂件会走「非 SSE 响应」的降级分支，所以现象是"能出字但一次性出现"。

---

## 点了"停止"停不下来

说明 `AbortSignal` 没有透传到上游 `fetch`。自定义 transport 时把 `ctx.signal` 传进 fetch 的 `signal` 选项——挂件在用户点停止时会 abort 它。后端侧也应该相应关闭到上游的连接，否则上游还在算，钱照付。

---

## 手机上输入框被键盘顶掉

挂件在 ≤520px 时切全屏布局，输入区用了 `env(safe-area-inset-bottom)`。如果还是有问题：

- 检查站点有没有 `viewport` meta 里的 `interactive-widget` 之类的自定义设置。
- 检查挂件是不是被塞进了一个高度写死的容器里（应该挂在 `body` 上）。

---

## 会话串了 / 刷新后还在

自建挂件默认把对话存在 `sessionStorage`（按 `sessionKey`，默认 `waa:session`）。

- **想每次刷新都清空**：`persist: false`。
- **同域多个挂件互相串**：给每个挂件不同的 `sessionKey`。
- **想跨页保留但关标签页就清**：`sessionStorage` 就是这个语义，符合预期。

---

## 点面板外面不关 / 不该关的时候关了

自建挂件默认 `closeOnOutsideClick: true`，靠的是 document 上的 `pointerdown`。
Shadow DOM 会把内部点击的 target 重定向成宿主元素，所以判断是"点没点在挂件里"。

- **点外面不关**：先确认没把 `closeOnOutsideClick` 设成 `false`。再确认站点没有在
  捕获阶段 `stopPropagation()` 掉 document 上的 pointerdown（少数全站手势库会这么干）。
- **点面板里面也关**：说明判断用的是 light DOM 的 `contains` 而 target 没被重定向——
  这种情况只会出现在你自己改过挂载方式（比如把内容从 Shadow DOM 里搬出来）之后。
- **点自己的下拉/弹层被关掉**：挂件只认自己 Shadow Root 里的内容。如果你的业务弹层
  是挂在 `document.body` 上的，点它会被判定成"外部点击"。把它的选择器传给 `outsideIgnore`
  即可豁免：`mount({ outsideIgnore: ['.my-datepicker', '#my-dropdown'] })`。

## 历史记录或记忆丢了 / 串了

存储是 `storageKey`（默认 `waa`）下的一个 JSON，用 `storage` 决定放 sessionStorage 还是 localStorage。

- **刷新后历史没了**：`storage` 是 `'session'`（默认），关掉标签页就会清。要跨访问保留就设成 `'local'`。
- **换个页面历史还在但看着不对**：确认两个页面用的是同一个 `storageKey`（默认相同，所以是共享的，这通常是你想要的）。
- **同域两个挂件互相串**：给它们不同的 `storageKey`。
- **隐私模式/无痕下不保存**：挂件的存储层会探测可用性，不可用时自动降级成"不保存"，
  功能照常但不持久。这是有意为之，不要试图绕过。
- **记忆越来越长、把回答带偏**：记忆是每次请求都会带上的文本。只记稳定事实
  （他是谁、买过什么、偏好什么），别把临时状态写进去。

## 热词不显示

- **配了 `hotWordsUrl` 但拉不到**：挂件会静默回退到静态 `hotWords`。两个都没配就是没有热词条，这是正常的。
- **CORS**：跨域拉热词要后端放行，否则会被浏览器拦掉（表现就是只有静态兜底那几条）。
- **`hotWordsPlacement` 设成了 `'off'`**：直接不渲染。
- **对话开始后热词条消失**：`'empty'` 模式只在空态显示。想让它在对话中也常驻，用 `'both'` 或 `'composer'`。

## 参考资料不出现

- **后端根本没返回引用**：挂件只负责显示，检索要你自己做。
- **返回了但字段名不认识**：内置实现只认 `references` / `citations` / `sources` /
  `search_info` / `doc_references` 这几种。用别的字段名就在自定义 transport 里
  调 `ctx.onReferences(list)`。
- **流式下引用在最后一帧才给**：界面会在收到时就渲染，但如果回复已经结束才给，会跟着那条消息一起渲染——没问题，只是用户看不到"边流边给引用"的效果。
- **点不开链接**：`url` 字段为空时只显示标题和摘要，这是有意的（宁可不显示链接，也不给死链）。

## 快捷键不生效 / 抢了站点的键

- **`mod+K` 没反应**：先确认 `shortcuts` 不是 `false`。再看站点有没有在 window 上截获 keydown 并
  `stopPropagation()`（少数全站快捷键库会这么干）——挂件监听在 document 上，站点在更外层截获就收不到。
- **按了没反应但也不报错**：多半是**焦点在站点自己的输入框里**。这是有意为之：全局键不会抢站点输入框里的按键，
  否则会把人家搜索框的 `Ctrl+K` 吃掉。点一下页面空白处再试。
- **中文输入时按 Enter 误发消息**：挂件会忽略 `isComposing` 阶段的事件。如果还误发，是站点自己
  preventDefault 掉了 composition 事件，或者你重绑了 `send`（不要绑到裸 `enter` 之外还加别的前缀）。
- **想换键**：`hotkeys: { toggle: 'mod+shift+k' }`；想彻底禁用某个动作传 `false`。
- **和站点自己的快捷键撞了**：优先改我们的（`hotkeys`），别去改站点——这条边界要保持。
  只有站点明确同意时才动它。
- **复制 / 粘贴 / 剪切失效**：正常情况挂件不绑也不拦这些键（`Ctrl/⌘ + C/X/V/A/Z`）。
  如果确实坏了，按顺序查：① 站点自己有没有全局拦截 keydown；② `hotkeys` 里有没有人把
  动作绑到这些组合键上——绑了会被拒绝并打告警，看控制台有没有那条 warn；
  ③ 站点是不是在 `http` 内网域名下跑，导致剪贴板 API 不可用（挂件的代码块复制按钮有
  `execCommand` 兜底，但系统级的 `Ctrl+V` 不受挂件控制）。

## 排查完还是不行

收集四样东西再去问人（没有这四样很难定位）：

1. F12 Console 的完整报错。
2. F12 Network 里那条失败请求的 **URL + 状态码 + 响应体前几行**。
3. 你在哪个页面、点了什么、期望什么、实际什么。
4. 挂件的接入方式（官方 AppFlow 挂件还是自建、配置片段）。
