# 阿里云控制台配置（你点不了，交给用户）

路径 A 的前置条件。Agent 无法登录控制台，所以这一步的产出是**一份用户照着能走完的清单**，而不是替用户点。

写清单时的原则：说清"在哪个产品的哪个页面、点什么按钮、抄下什么值、填到哪去"。用户最常卡住的地方是"不知道哪个值对应哪个字段"，所以每一步都要点明产出的值的名字。

## 全局图

```
百炼：创建智能体应用  ──►  应用 ID  ─┐
                                    ├──►  AppFlow：AI 助手 → 导入模型
百炼：创建 API Key    ──►  API Key  ─┘         │
                                               ▼
                                    页面集成（拿 integrateId + requestDomain）
                                               │
                                               ▼
                                        插进网站的两段代码
                                               │
                              （可选）知识库 → 挂到应用 → 让答案有依据
```

计费提醒：百炼新用户有免费额度，覆盖教程量级的调用；AppFlow、函数计算 FC、以及可选的 ADB-PG 向量存储是**分别计费**的。用户如果在意成本，先把这句告诉他，别等出账单。

## 第 1 步 · 创建百炼应用

1. 百炼控制台 → **应用管理** → 右上角 **创建应用** → 选 **智能体应用** → 输入应用名称 → **立即创建**（其余保持默认）。
2. 进入 **应用配置** 页 → **更多模型** → 选择模型。教程用 `Qwen3.5-Plus`（能力/成本/速度介于千问 Max 与 Flash 之间，适合客服场景）。模型名会随百炼更新，以控制台当前可选项为准，不要写死一个可能下线的名字进文档。
3. 在 **Prompt** 里写角色设定，例如：

   ```
   你叫小助，可以帮助用户解答产品选购、使用等方面的问题。
   ```

   这里要按用户的真实业务改。让用户提供：助手叫什么、服务什么产品、**不该答什么**（越界问题的兜底话术）。最后一条最容易被漏，但它决定了助手会不会满嘴瞎编。
4. 右侧对话框试几个问题验证。此时它还答不出公司内部信息——正常，第 4 步用知识库解决。
5. 右上角 **发布**。

**产出值：应用 ID**（在应用管理页面上可以看到所有应用的 ID）。

## 第 2 步 · 创建 API Key

百炼 → **密钥管理** → **创建 API Key** → 弹窗里创建 → 复制保存。

**产出值：API Key。**

两个必须提醒用户的点：

- API Key 只在创建时完整显示一次，关掉弹窗就看不全了。
- **API Key 等同于账号下的调用能力**，不要提交进 Git、不要贴进前端代码、不要发给别人。这个 skill 的自建路径会把 key 放后端，就是为了这件事。

## 第 3 步 · 在 AppFlow 创建 AI 助手

AppFlow 不用写代码就能把网页和模型服务平台连起来。

1. 登录 **AppFlow 控制台** → 左侧导航 **模型服务** → **AI 助手**。
2. **创建 AI 助手** → 设置基本信息（图标、名称）→ **提交** → 进入 AI 助手详情页。
3. 详情页点 **导入模型** → 选 **阿里云百炼** → 确定。（也可选其他平台作为模型服务提供方。）
4. **连接凭证** → **添加新凭证** → 填凭证名称 + 第 2 步的 **API Key**。创建后以后可复用同一凭证。
5. 填入第 1 步的 **应用 ID** → 确定，把百炼应用与 AI 助手关联。
6. **页面集成** → 选 **web 页面集成** → **创建集成** → 输入集成名称 → 确定，进入详情配置页。
7. 对照右方可视化界面调效果：字体颜色、背景颜色、嵌入界面大小、头像图标、**预置问题**。调完点 **提交**。

**产出值：`integrateId`、`requestDomain`。**

「预置问题」值得认真填——它是访客的第一个入口，比任何欢迎语都有用。让用户按真实高频问题给 2–3 条。

## 第 4 步 · 拿到部署脚本

回到 **AI 助手 → Web 集成** 页面，**最底部**找到 **登录配置**：

- 点 **匿名方式** → 复制 **悬浮挂件部署脚本**。

这一份脚本就是路径 A 要插进网站的东西。**必须来自用户自己的集成页面**——从别处抄来的示例脚本里的 `requestDomain` 是别人的域名，必然报 `Failed to stream content`。

登录配置另有需要鉴权的方式，适合"只有登录用户能用助手"的场景；匿名方式适合公开站点。

## 第 5 步（可选）· 加私有知识，做 RAG

到这一步助手已经能对话了，但它只会通用知识。要让它像公司员工一样答得准，需要给它喂文档。

1. **数据连接** → **默认文件连接器** → **详情**。
2. 右上角 **导入数据** → 上传文档。（上传后百炼需要解析，通常 1–6 分钟，让用户耐心等，别以为卡死了。）
3. **知识库** → **创建知识库**（首次是"立即开通并创建"）→ 选 **标准版** → 填名称与描述 → 下一步 → 选刚上传的文档 → 索引设置保持默认。
   - 向量存储类型：要集中管理多个应用的向量数据可选 **ADB-PG**；不清楚就用默认。
4. **应用管理** → 选中之前的应用 → 在 **文档** 中挂上目标知识库 → 调用方式选 **必定调用** → 测试验证 → **发布**。

「必定调用」还是「按需调用」：必定调用让每次提问都检索知识库，答案更贴资料但更慢更贵；按需调用让模型自己判断。客服场景一般用必定调用。

## 上线前建议

组织业务人员做一轮**人工评测**（这也是百炼控制台里能做的事），拿真实高频问题问一遍，确认答案符合预期再上线。

效果不满意时的三个杠杆，按性价比排序：

1. **优化 Prompt** —— 改角色设定、加限制条件，最便宜见效最快。
2. **补私有知识** —— 缺什么文档补什么。
3. **调整文档切分策略** —— 前面的都没用再动这个，它最玄学。

## 让 agent 参与的部分

控制台走完之后，真正能自动化的部分是：

- 把部署脚本**正确地**插进用户的站点（时序、位置、SPA 只 init 一次）。
- 按业务补 `setUser` / `setExtraInfo` / `onBeforeSend` / `onAfterSend`。
- 排查故障（见 `troubleshooting.md`）。
- 如果用户没有 AppFlow、或不想依赖外部托管，改成自建路径（见 `self-hosted-widget.md`）。
